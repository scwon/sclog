# 방문자 브라우저에는 설정과 읽기 기록만 다음 방문까지 남긴다

블로그는 서버 저장소 없이 방문자 브라우저에만 기억을 남긴다. 무엇을 얼마나 오래 둘지는 성격에 따라 나눴다. 방문자가 직접 고른 **설정**(테마, 패널 너비)과 **읽기 기록**(읽은 글, 글마다 마지막으로 읽은 위치)은 `localStorage`에 두어 다음 방문까지 남긴다. **창 배치**(열린 탭, 마지막 패널 화면)는 `sessionStorage`에 두어 세션이 끝나면 사라지게 했다. IDE도 설정은 오래 들고 가고 창 배치는 작업 단위로 다루는데, 다음 방문에 지난 탭이 잔뜩 열려 있으면 첫 화면이 어수선해진다. 방문자 브라우저에 한번 남은 키는 우리가 거둘 수 없으므로 이 경계를 먼저 정해 둔다.

## Considered Options

- **열린 탭도 다음 방문까지 남기기**: VS Code처럼 작업 공간을 되살리는 느낌은 나지만, 다시 온 방문자가 처음 보는 화면이 지난번 탭 더미가 된다. 1차 묶음의 "탭 유지" 후보는 이 때문에 뺐다.
- **마지막 패널 화면을 저장하지 않기**(프로필 스펙의 처음 결정): 새로고침하면 탭은 남는데 패널만 탐색기로 돌아가서, 같은 창 배치 안에서 기억이 어긋난다.
- **글을 열기만 해도 읽은 글로 치기**: 금방 모든 글에 표시가 붙어 구분하는 뜻이 사라진다.

## Consequences

- **읽은 글**은 읽은 비율 90% 이상에 닿은 글이다. 기한 없이 남긴다.
- 마지막 읽은 위치는 픽셀이 아니라 장 id와 읽은 비율로 둔다. 화면 폭이 바뀌어도 같은 곳을 가리키게 하려는 것이다. 최근 20편까지만 두고, 그 글을 끝까지 읽으면 지운다.
- 키 이름은 접두사 없이 짧게 쓴다(`theme`, `tabs`, `read`, `position`, `panel`, `panel-width`). 이 도메인을 블로그 혼자 쓰고, `theme`을 바꾸면 기존 방문자의 테마가 초기화된다. 구조가 있는 값은 JSON 안에 `v` 판 번호를 넣고, 모양이 틀리거나 이제 없는 글을 가리키는 값은 불러올 때 버린다.
- 저장소를 쓸 수 없으면(사생활 보호 창 등) 안내 없이 메모리에만 둔다.
- 읽기 기록은 페이지를 불러올 때 한 번 읽는다. 다른 브라우저 탭의 변경은 실시간으로 따라가지 않는다.
- 방문자는 읽기 기록을 한 번에 지울 수 있어야 한다. 테마는 전환 버튼으로 충분하다.

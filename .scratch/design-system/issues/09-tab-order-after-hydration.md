# 09: 하이드레이션 직후 탭 순서가 한 번 바뀌는 문제

**What to build:** 탭을 여러 개 연 채 글로 바로 들어오거나 새로고침해도 탭 표시줄의 활성 탭 위치가 움직이지 않는다.

**Blocked by:** 없음

**Status:** wontfix

참고: 티켓 08 Comments의 코드 리뷰 "남긴 것", `src/design-system/components/Tabs/Tabs.tsx`의 `serverState(current)`.

## 현상

- 서버 HTML의 탭 표시줄은 `[posts.log, 지금 화면의 파일]` 두 칸이다. 서버는 sessionStorage에 저장된 탭을 모르기 때문이다.
- 하이드레이션 뒤에는 저장된 순서(`[posts.log, A, B, 지금 화면의 파일, C]` 등)로 다시 그린다. 그래서 활성 탭이 두 번째 칸에서 제자리로 한 번 옮겨 간다.
- 하이드레이션 불일치는 없다. 서버와 첫 클라이언트 렌더가 같은 스냅샷(`useStore`의 `ssr`)을 쓴다.
- 탭이 두 개 이하이면 보이지 않는다.

## 정할 것

고칠지, 고친다면 방법 중 무엇을 고를지 정한다.

- 그대로 둔다: 순간적이고 탭이 많을 때만 보인다.
- 하이드레이션 전까지 서버 탭 표시줄의 나머지 칸을 비워 두고, 저장된 탭은 오른쪽에서 드러나게 한다(이미 있는 새 탭 등장 모션을 재사용).
- 테마 초기 스크립트처럼 인라인 스크립트가 첫 페인트 전에 sessionStorage를 읽어 탭 표시줄을 그린다. 창 틀 아일랜드 밖에 상태를 하나 더 두게 된다(ADR 0001 확인 필요).

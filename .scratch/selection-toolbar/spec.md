# 본문 선택 툴바

Status: done

글 본문에서 글자를 드래그하면 고른 줄들을 상자로 감싸고, 상자 오른쪽에 동작 버튼을 띄운다. 1차 동작은 복사 하나다. 툴바는 동작 목록을 받아 그리는 틀이라서 연관 내용 검색 같은 동작을 나중에 하나씩 꽂는다. 용어는 `GLOSSARY.md`를 따른다.

2026-10-27 블로그 주인과 인터뷰로 정했다. 링크·공유 쪽 조사는 [`docs/research/text-fragment-links.md`](../../docs/research/text-fragment-links.md)에 있다.

## Problem Statement

글을 읽다 한 대목을 옮기려면 드래그한 뒤 ⌘C나 우클릭 메뉴를 찾아야 한다. 무엇을 골랐는지 브라우저 기본 선택색 말고는 표시가 약하고, 고른 대목에 바로 할 수 있는 일이 없다. 앞으로 고른 대목으로 연관 글을 찾는 기능을 붙이려 해도 그 동작을 둘 자리가 없다.

## Solution

`.doc-prose` 안에서 글자를 고르면 고른 줄들을 본문 폭 상자 하나로 감싼다. 상자는 본문 위에 겹친 층에 그려서 레이아웃이 한 픽셀도 움직이지 않는다. 상자 오른쪽 여백, 마우스를 놓은 줄 높이에 복사 버튼이 뜬다. 누르면 고른 글자를 평문 그대로 클립보드에 넣고, 버튼 아이콘이 체크로 바뀌며 화면 아래에 토스트가 뜬다.

## User Stories

1. 독자로서, 본문을 드래그하면 고른 줄들이 상자로 감싸이기를 바란다. 그래야 무엇을 골랐는지 또렷하다.
2. 독자로서, 상자가 생기고 사라질 때 글이 흔들리지 않기를 바란다.
3. 독자로서, 왼쪽에서 오른쪽으로 드래그를 마친 자리 가까이, 상자 오른쪽에 버튼이 있기를 바란다. 그래야 마우스를 멀리 옮기지 않는다.
4. 독자로서, 복사 버튼을 누르면 고른 글자가 출처 없이 그대로 복사되기를 바란다.
5. 독자로서, 복사되면 버튼이 체크로 바뀌고 토스트가 떠서 됐다는 것을 알고 싶다. 복사가 막히면 ⌘C를 쓰라는 안내를 보고 싶다.
6. 독자로서, 복사한 뒤에도 선택을 유지하는 동안 툴바가 남아 있기를 바란다.
7. 독자로서, 선택을 풀거나 Esc를 누르거나 다른 글로 옮기거나 ⌘F를 누르면 상자와 버튼이 사라지기를 바란다.
8. 키보드 사용자로서, Shift+화살표로 골라도 툴바가 뜨고 포커스는 본문에 남기를 바란다.
9. 스크린 리더 사용자로서, 버튼이 "복사"로 읽히고 복사 결과가 알려지기를 바란다.
10. 독자로서, 코드 블록·표·제목·목차를 고르거나 두세 글자만 골랐을 때는 툴바가 뜨지 않기를 바란다. 코드 블록에는 이미 복사 버튼이 있다.
11. 휴대폰 독자로서, OS 선택 메뉴와 같은 버튼이 겹쳐 뜨지 않기를 바란다.
12. 블로그 주인으로서, 나중에 동작 하나만 등록하면 툴바에 버튼이 늘기를 바란다.

## Implementation Decisions

### 언제 뜨는가(순수 모듈)

- 판정 입력은 선택 범위의 시작·끝 노드, 고른 글자, 포인터 종류다. DOM 접근은 얇은 어댑터에 두고 판정은 순수 함수로 테스트한다.
- 뜨는 조건: 시작과 끝이 모두 `.doc-prose` 안이고, 어느 쪽도 `pre`·`code` 블록·`table`·제목 요소·목차 안이 아니며, 공백을 뺀 글자가 3자 이상이다. 코드 블록 틀(`.code-block-wrapper`)처럼 블로그가 붙이는 제외 요소와 층을 붙일 글 요소(`[data-doc]`)는 소비자가 `watchSelectionToolbar` 설정으로 넘긴다. 디자인 시스템 안에 블로그 선택자를 두지 않는다.
- 시작과 끝이 모두 본문 글자에 있으면 사이에 코드 블록이나 표가 끼어 있어도 툴바를 띄우고, 복사는 그 사이까지 모두 평문으로 가져간다. 판정은 두 끝만 본다.
- `(pointer: coarse)`에서는 띄우지 않는다. 동작마다 `mobile` 표시를 두고, 이 표시가 켜진 동작이 생기면 그때 아래 고정 바를 연다(1차에는 없다).
- `selectionchange`를 듣되 마우스 드래그 중에는 그리지 않고 `pointerup`에서 그린다. 키보드 선택은 `selectionchange`를 짧게 미뤄(debounce) 그린다.

### 상자

- 본문 위에 `position: absolute`, `pointer-events: none` 층 하나를 두고 상자를 그린다. 본문 DOM과 레이아웃은 건드리지 않는다. 스크롤하면 문서와 함께 움직인다.
- 상자 높이는 선택 범위 `getClientRects()`의 첫 줄 위에서 끝 줄 아래까지, 폭은 본문 단 전체다. 여러 문단에 걸쳐도 상자는 하나다. 모서리는 둥글고 테두리와 옅은 바탕을 쓴다. 색은 토큰에서 가져오고 두 테마 대비를 확인한다.
- 나머지 본문은 흐리게 하지 않는다.
- rect 목록에서 상자와 버튼 자리를 계산하는 함수는 순수 함수로 둔다.
- 하이라이트 이름이 필요하면 ⌘F 찾기의 `find-match`·`find-current`와 겹치지 않게 짓는다.

### 버튼 자리

- 가로는 상자 오른쪽 바깥 여백에 고정한다. 세로는 선택의 끝(`selection.focusNode`, 마우스를 놓은 줄)에 맞춘다. 위로 드래그하면 끝이 첫 줄이 된다.
- 세로 위치는 화면 안으로 묶는다(clamp). 상자가 화면보다 길어도 버튼은 보인다.
- 오른쪽 여백이 버튼 폭보다 좁으면 상자 안쪽 오른쪽 위로 들인다.
- 디자인 시스템에 Radix Popover 래퍼를 새로 두고 가상 기준점(virtual anchor), `side="right"`, `align="start"`로 띄운다. 새 의존성 없이 `radix-ui` 묶음을 쓴다.
- 툴바가 떠도 포커스를 가져가지 않는다. Tab으로 들어갈 수 있다. 버튼 묶음은 랜드마크 안에 있도록 글 요소 끝에 포털되므로, 키보드 사용자에게는 고른 자리 바로 뒤에 놓인 것처럼 Tab 순서를 잇는다. 키 판정은 모두 `shortcutFor`가 한다.
  - 고른 자리에서 누른 첫 Tab은 툴바 첫 버튼으로 간다. 툴바 청크를 아직 불러오는 중이면 그린 뒤 보내고, 그 사이에 선택이 바뀌거나 툴바가 걷히거나 포커스가 옮겨 갔으면 보내지 않는다.
  - 마지막 버튼의 Tab은 문서 순서로 선택 끝 뒤에 오는 첫 Tab 대상(툴바 밖)으로 간다. 그런 대상이 없으면 브라우저가 받는다.
  - 첫 버튼의 Shift+Tab은 고른 글자를 품은 요소(에디터 루트 또는 `body`)로 돌아간다. 선택은 남고, 다시 Tab을 누르면 툴바로 들어간다.
  - 버튼 사이의 Tab과 툴바에 들어가지 않은 Tab·Shift+Tab은 브라우저가 받는다. 포커스를 가두지 않는다.

### 동작 구조

- 동작은 `{ id, label, icon, mobile, when(ctx), run(ctx), done? }`이다. 툴바는 `when`이 참인 동작만 순서대로 그린다. `run`은 됐는지를 참·거짓(또는 그 Promise)으로 돌려주고, 참이면 버튼이 잠시 `done: { label, icon }`으로 바뀐다(복사 → 복사됨·체크). 복사가 막혀 거짓을 돌려주면 바뀌지 않는다.
- 선택 정보 `ctx`는 고른 글자, 글 slug, 선택 바로 위 제목 id를 담는다. 제목 id는 나중의 절 링크·연관 검색용이다.
- 1차 동작은 `copy` 하나다. `navigator.clipboard.writeText`로 평문만 넣는다. 앞뒤에 출처·링크를 붙이지 않는다.

### 피드백: Toast

- 디자인 시스템에 Toast를 새로 만든다. Radix Toast를 감싸고 공유 상태는 `stores/`의 nanostore에 둔다. 화면 아래 가운데, 약 2초 뒤 사라지고 스크린 리더에 알린다.
- 복사가 되면 버튼 아이콘을 체크로 바꾸고(`CodeBlock.astro`와 같은 방식) 토스트 "복사했어요"를 띄운다. 클립보드가 막히면 토스트로 ⌘C 안내를 띄운다.
- 코드 블록 복사·제목 링크 복사를 토스트로 옮기는 일은 이 스펙 밖이다.

### 닫힘과 화면 이동

- 선택이 접히면(빈 곳 클릭 포함), Esc, `astro:before-swap`, 찾기 줄이나 팔레트가 열리면 상자와 툴바를 걷는다. 복사 뒤에는 닫지 않는다.
- Esc 층 순서는 툴바 → 팔레트 → 좁은 화면의 겹침 패널 → 찾기 줄이다. 팔레트가 열릴 때 툴바를 걷으므로 둘이 함께 떠 있지는 않다. 키 판정은 `shortcutFor` 하나에 더하고 리스너를 새로 걸지 않는다. `docs/agents/shortcuts.md`를 먼저 읽고 고친다.
- 화면 이동 규칙은 `docs/agents/astro-client-router.md`를 따른다. 리스너는 페이지를 옮겨도 하나만 남아야 한다.

### 찾기 기능과의 경계

- 하이라이트 이름과 색을 찾기와 나눈다.
- 찾기 줄이 열리면 툴바를 닫는다. 툴바가 떠 있을 때 ⌘F를 누르면 지금처럼 고른 글자가 검색어로 들어간다.
- "이 대목 찾기"는 1차에 넣지 않는다. 동작 구조에 나중에 꽂는다.

### 문서

- `GLOSSARY.md`에 **선택 툴바 (selection toolbar)**를 더한다: 본문에서 고른 대목을 감싸고 그 옆에 동작 버튼을 띄우는 것.
- `docs/agents/shortcuts.md`의 Esc 층 순서를 고친다.

## Testing Decisions

- **1층(Vitest)**: 뜨는지 판정(범위 밖, 코드·표·제목, 3자 미만, coarse 포인터), rect 목록 → 상자와 버튼 자리(여러 줄, 위로 드래그, 화면 밖 clamp, 좁은 여백에서 안으로 들이기), `when`에 따른 동작 목록, Esc 층 순서, 토스트 store.
- **2층(빌드 결과물)**: 툴바 청크가 첫 화면에서 정적으로 불리지 않는다.
- **3층(`pnpm qa`)**: 글에서 드래그 → 상자와 복사 버튼 → 누르면 체크와 토스트 → Esc로 닫힘. 상자가 생기기 전후로 본문 요소 위치가 같다. 툴바가 떠 있는 상태를 세 폭 × 두 테마 axe에 넣는다.

## Out of Scope

- 공유. 글 단위·Markdown 문단 단위 공유로 따로 한다.
- 절 단위 링크, 텍스트 조각 링크(`#:~:text=`).
- 인용 복사, 출처 붙이기, 이미지 카드, 하이라이트 저장.
- 연관 내용 검색(동작 구조만 준비한다).
- 휴대폰용 툴바.
- 기존 복사 버튼을 토스트로 옮기기.

# 파일에서 찾기

Status: ready-for-agent

⌘F(윈도·리눅스는 Ctrl+F)를 브라우저 대신 창 틀이 받아 에디터에 연 파일 안에서 찾는 찾기 줄을 띄운다. 여러 파일에서 찾는 ⌘⇧F 검색 화면과 짝을 이룬다. 용어는 `GLOSSARY.md`를 따른다(창 틀, 에디터, 패널, 검색 화면, 명령 팔레트).

이 스펙은 [블로그 디테일 1차](../blog-details/spec.md) 스토리 35와 결정 티켓 [04 단축키 체계](../blog-details/issues/04-shortcut-scheme.md)의 "⌘F는 늘 브라우저가 받는다"를 뒤집는다. 2026-10-27에 블로그 주인이 정했다. 함께 정한 것은 두 가지다. 찾기 줄이 열려 있어도 ⌘F는 늘 창 틀이 받고 찾는 범위는 에디터에 연 파일 전체다.

## Problem Statement

⌘⇧F로 여러 글을 찾을 수 있게 되었지만 지금 읽는 글 안에서 찾으려면 브라우저 찾기를 써야 한다. 브라우저 찾기는 창 틀의 탐색기·개요·상태줄 글자까지 함께 찾아서 일치 수가 부풀고 결과가 패널로 튄다. 한글을 조합하는 중이면 "개바"로 "개발"을 찾지 못해서 검색 화면과 규칙도 어긋난다. IDE처럼 생긴 창에서 ⌘F만 브라우저 창이 뜨는 것도 비유를 깬다.

## Solution

⌘F를 누르면 에디터 오른쪽 위에 찾기 줄이 뜨고 입력창에 포커스가 간다. 입력한 글자는 에디터에 보이는 글자에서만 찾는다. 모든 일치를 형광 띠로 칠하고 지금 일치는 한 단계 진하게 칠해 화면 안으로 가져온다. 찾기 줄에는 `3/12` 같은 위치가 보인다. Enter와 Shift+Enter로 다음·이전 일치로 가고 Esc로 닫는다. 일치 규칙은 검색 화면과 같다.

칠하기는 CSS Custom Highlight API로 해서 본문 DOM을 건드리지 않는다. 이 API가 없는 브라우저에서는 ⌘F를 가로채지 않고 브라우저 찾기에 맡긴다.

## User Stories

1. 독자로서, ⌘F(Ctrl+F)를 누르면 에디터 오른쪽 위에 찾기 줄이 뜨고 입력창에 포커스가 가기를 바란다. 그래야 IDE에서처럼 지금 파일 안을 찾는다.
2. 독자로서, 탐색기·개요·상태줄 글자는 빼고 에디터에 연 파일의 글자에서만 찾기를 바란다. 그래야 일치 수가 정확하다.
3. 독자로서, 한 글자부터 결과가 나오기를 바란다. 그래야 짧은 낱말도 바로 찾는다.
4. 독자로서, 입력 중인 음절("개바")로도 "개발"을 찾고 싶다. 그래야 검색 화면과 같은 감각으로 찾는다.
5. 독자로서, 모든 일치가 칠해지고 지금 일치는 더 진하게 보이기를 바란다. 그래야 어디가 지금 위치인지 안다.
6. 독자로서, 찾기 줄에서 `3/12`처럼 지금 위치와 전체 수를 보고 싶다. 일치가 없으면 `결과 없음`을 보고 싶다.
7. 독자로서, Enter로 다음, Shift+Enter로 이전 일치로 가고 끝에서는 처음으로 돌아가기를 바란다.
8. 독자로서, 지금 일치가 화면 밖이면 그 줄이 화면 가운데로 오기를 바란다. 위쪽 막대에 가려지지 않아야 한다.
9. 독자로서, 찾기 줄의 위·아래·닫기 버튼을 마우스로도 누르고 싶다.
10. 독자로서, Esc로 찾기 줄을 닫으면 칠한 것이 사라지고 포커스가 에디터로 돌아오기를 바란다.
11. 독자로서, 찾기 줄이 열린 채 ⌘F를 다시 누르면 입력창으로 포커스가 돌아오고 글자가 모두 선택되기를 바란다. 그래야 새 검색어를 바로 친다.
12. 독자로서, 에디터에서 글자를 고른 채 ⌘F를 누르면 그 글자가 검색어로 들어가기를 바란다.
13. 독자로서, ⌘G와 ⇧⌘G(Ctrl+G, Ctrl+Shift+G)로 찾기 줄 밖에서도 다음·이전 일치로 가고 싶다.
14. 독자로서, 다른 파일로 옮기면 찾기 줄이 닫히고 다음에 ⌘F를 누르면 마지막 검색어가 들어 있기를 바란다.
15. 독자로서, 팔레트 명령 목록에서 `이 파일에서 찾기 ⌘F`를 보고 실행하고 싶다. 그래야 ⌘F가 바뀐 것을 배운다.
16. 스크린 리더 사용자로서, 입력창이 "파일에서 찾기"로 읽히고 `3/12` 위치 변화가 알려지기를 바란다.
17. 좁은 화면의 독자로서, 찾기 줄이 에디터 폭에 맞춰 줄어들기를 바란다. 겹침 패널이 열려 있을 때 ⌘F를 누르면 겹침 패널이 닫히고 찾기 줄이 뜨기를 바란다.
18. 오래된 브라우저의 독자로서, 우리 찾기를 쓸 수 없으면 ⌘F가 지금처럼 브라우저 찾기를 열기를 바란다.

## Implementation Decisions

### 키

- 붙이는 키: ⌘F 찾기 줄 열기, ⌘G·⇧⌘G 다음·이전 일치. `docs/agents/shortcuts.md`의 기준 4번(⌘F는 건드리지 않음)과 5번(가로채는 키는 ⌘P·⌘B뿐)을 이 결정에 맞게 고치고 겹침 확인표에 ⌘F(세 브라우저 모두 페이지 찾기, 가로챈다)와 ⌘G(브라우저 다음 찾기, 가로챈다) 줄을 더한다.
- 판정은 지금의 `shortcutFor` 하나에 더한다. 리스너를 새로 걸지 않는다. 키는 `SHORTCUT_KEYS`에 `find`로 둔다. `CSS.highlights`가 없으면 판정이 ⌘F·⌘G를 `null`로 돌려 브라우저에 맡긴다(맥락에 지원 여부를 넣는다).
- 찾기 줄 입력창(`data-find-input`)은 새 포커스 종류다. Enter·Shift+Enter·Esc·⌘F·⌘G·⇧⌘G를 받고 나머지 글자는 입력창이 받는다. 검색 입력창·팔레트 입력창에 포커스가 있어도 ⌘F는 찾기 줄을 연다. 그 밖의 입력창에서는 지금처럼 끈다.
- 팔레트가 열려 있으면 ⌘F·⌘G는 기본 동작만 막는다(열린 팔레트의 ⌘P와 같다).
- Esc 층 순서는 팔레트 → 좁은 화면의 겹침 패널 → 찾기 줄이다.
- ⌘G·⇧⌘G는 찾기 줄이 닫혀 있으면 마지막 검색어로 찾기 줄을 열고 다음·이전으로 간다. 마지막 검색어가 없으면 찾기 줄만 연다.

### 찾기 규칙(순수 모듈)

- 검색 화면과 같은 `match.logic.ts`의 `matchRanges`를 쓴다. NFD 부분 일치, 대소문자 무시, 음절 단위로 넓히기가 같다. 앞뒤 공백만 지우고 한 글자부터 찾는다.
- 에디터 글자는 텍스트 노드 목록과 그 이어 붙인 문자열로 만든다. 일치 범위를 노드·오프셋 쌍으로 되돌리는 함수는 DOM을 모르는 순수 함수로 두고 단위 테스트로 덮는다. 블록 경계(문단 끝)를 넘는 일치는 만들지 않는다.
- 찾는 글자는 브라우저 찾기처럼 화면에 보이는 글자다. `aria-hidden`이어도 보이면 찾고(frontmatter 줄), `.sr-only`·`hidden`·`display: none` 글자와 줄 번호는 뺀다. 닫힌 `<details>` 안은 찾지 않는다.
- 다음·이전 이동은 끝에서 처음(처음에서 끝)으로 돈다. 검색어가 바뀌면 지금 일치는 화면 맨 위에 보이는 일치부터 시작한다.

### 찾기 줄

- 창 틀이 그리는 디자인 시스템 컴포넌트다. 찾는 영역은 `#editor`다. 찾기 줄은 처음 쓸 때 불러오는 청크로 나누고 첫 화면 JS에 넣지 않는다.
- 자리는 에디터 오른쪽 위, 탭 줄과 경로 줄 아래다. 폭은 360px 안팎이고 좁은 화면에서는 에디터 폭에서 양옆 8px을 뺀 만큼 줄어든다.
- 안은 입력창(안내 문구 "파일에서 찾기"), 위치 글자(`3/12`, 없으면 `결과 없음`, 검색어가 비면 비움), 이전·다음·닫기 버튼이다. 버튼 이름은 `이전 일치 (⇧Enter)`·`다음 일치 (Enter)`·`찾기 닫기 (Esc)`이고 키 표기는 `(hover: hover) and (pointer: fine)`일 때만 툴팁에 넣는다.
- 위치 글자는 `aria-live="polite"`로 알린다. 입력창은 `role="searchbox"`다.
- 칠하기: 모든 일치는 `Highlight` 하나(`find-match`)에 담아 검색 화면 발췌와 같은 형광 띠 `--marker`로 칠한다. 지금 일치는 다른 `Highlight`(`find-current`)에 담아 `--accent` 바탕과 `--on-accent` 글자로 칠한다. 두 테마에서 글자와 바탕의 명암비가 4.5 이상인지 토큰 테스트가 본다.
- 스크롤: 지금 일치의 사각형이 에디터 보이는 영역 밖이면 그 줄을 보이는 영역 가운데로 옮긴다. 움직임 줄이기 설정에서는 바로 옮긴다. 위쪽 막대 높이(`--bar-height` 등)를 빼고 계산한다.
- 닫기: 칠한 것을 지우고 포커스를 찾기 줄을 연 자리로 돌려준다. 연 자리가 없으면 에디터로 간다.
- 열 때 에디터 안에서 고른 글자가 있고 한 줄이면 그 글자를 검색어로 넣는다. 없으면 마지막 검색어를 넣고 모두 선택한다.

### 화면 이동과 기억

- 다른 파일로 옮기면(`astro:before-swap`) 찾기 줄을 닫고 칠한 것을 지운다. 마지막 검색어는 창 틀 메모리에만 두고 저장하지 않는다(새로고침하면 비워진다). ADR 0004의 "저장하지 않는 것"에 해당한다.
- 화면 이동 규칙은 `docs/agents/astro-client-router.md`를 따른다.

### 명령 팔레트

- `>` 명령 목록의 `파일 열기 ⌘P` 다음에 `이 파일에서 찾기 ⌘F`를 넣는다. 늘 보인다(지원하지 않는 브라우저에서는 뺀다). 창 틀 명령 이름은 `find-in-file`이고 `runCommand`가 실행한다.

### 문서

- `GLOSSARY.md`에 **찾기 줄 (find widget)**을 더한다: 에디터에 연 파일 안을 찾는 창 틀의 입력 줄. ⌘F로 연다. 여러 파일을 찾는 검색 화면과 다르다.
- `docs/agents/shortcuts.md`의 "지금 붙은 키" 표에 ⌘F·⌘G·⇧⌘G를 더한다.
- 블로그 디테일 1차 스펙 Comments에 이 스펙이 스토리 35를 대신한다는 한 줄을 남긴다. 결정 티켓 04는 고치지 않는다(결정 기록은 바꾸지 않는다).

## Testing Decisions

경계는 블로그 디테일 1차 스펙의 세 층을 그대로 쓴다.

- **1층(순수 로직)**: 키 판정(⌘F·⌘G·⇧⌘G, 맥/그 밖, 찾기 입력창의 키, 팔레트 열림에서 기본 동작만 막기, 지원하지 않을 때 `null`, Esc 층 순서), 범위를 노드·오프셋으로 되돌리기(여러 노드에 걸친 일치, 블록 경계, 음절 넓히기), 다음·이전 순환과 시작 위치, 위치 글자(`3/12`, `결과 없음`), 명령 목록에 `find-in-file`이 들어가는 자리.
- **2층(빌드 결과물)**: 첫 화면 HTML과 다른 청크가 찾기 줄 청크를 미리·정적으로 불러오지 않는다.
- **3층(`pnpm qa`)**: 글에서 ⌘F → 입력창 포커스 → 검색어 입력 → 위치 글자와 칠하기(`CSS.highlights`의 범위 수) → Enter로 다음 → Esc로 닫히고 칠한 것이 사라짐. 화면을 옮기면 닫히고 다시 ⌘F를 누르면 마지막 검색어가 들어 있다. 찾기 줄이 열린 상태를 세 폭 × 두 테마 axe에 넣는다.

## Out of Scope

- 바꾸기, 정규식, 대소문자 구분·낱말 단위 옵션.
- 검색 화면 결과를 누를 때 찾기 줄을 그 검색어로 이어 여는 것.
- 닫힌 `<details>`를 열어 찾는 것.
- 터치 화면용 찾기 버튼. 키보드가 없으면 브라우저 메뉴의 찾기를 쓴다.

# 01: 정적 Astro 사이트에서 글 검색을 만드는 방법

**Type:** research

**Blocked by:** 없음

**Status:** resolved

지도: [블로그 디테일 1차](../map.md)

## Question

패널의 검색 화면과 명령 팔레트(⌘P)가 함께 쓸 글 검색을, 서버 없는 Astro 정적 사이트에서 어떻게 만들 수 있는가?

- 후보: Pagefind, 빌드 때 만든 JSON 색인 + 클라이언트 매칭(직접 또는 작은 라이브러리), 그 밖에 근거 있는 선택지
- 후보마다 확인할 것: 한국어(형태소·부분 일치) 검색 품질, 첫 사용 때 내려받는 크기, 지연 로딩 가능 여부, `<ClientRouter />` 화면 이동과 같이 쓸 수 있는지, 최근 3개월 안에 유지보수됐는지
- 파일 이름만 찾는 것(⌘P)과 본문까지 찾는 것(검색 화면)을 한 색인으로 할 수 있는지

결과는 `docs/research/blog-search.md`에 출처와 함께 남긴다.

## Answer

Pagefind를 쓰지 않는다. 런타임 의존성 없이 두 갈래로 만든다. 근거와 측정값은 브랜치 `research/blog-search`의 `docs/research/blog-search.md`에 있다.

- **⌘P 팔레트**: `Shell`이 이미 받는 `tree` props(모든 글의 url·title·path)를 그대로 검색한다. 따로 색인을 만들지 않는다.
- **패널 본문 검색**: 빌드 때 `/search-index.json`을 만든다. 검색 화면을 처음 열 때 받고, NFD로 바꾼 부분 문자열로 찾는다. 입력 중인 음절("개바"→"개발")과 띄어 쓰지 않은 복합어("발자"→"개발자")도 찾는다.
- **비용**: BM25 순위, 제목별 하위 결과, 강조, 필터를 직접 만들어야 한다. MDX를 순수 텍스트로 벗기는 코드도 유지해야 한다.
- **다시 볼 때**: JSON이 gzip 100KB(글 약 20편)를 넘으면 그때의 글로 Pagefind와 다시 잰다.
- **측정**: 지금 글 1편 기준으로 첫 검색 용량은 JSON 5.0KB, Pagefind 약 111KB(wasm 68KB)다. Pagefind 1.5.2는 한국어를 분절하지 않아서, 93편 시험 말뭉치에서는 한국어 첫 검색이 약 329KB였다.

# 18: 패널 검색 화면

**What to build:** 활동 막대의 돋보기(좁은 화면은 서랍의 `검색` 버튼)로 패널을 검색 화면으로 바꾼다. 두 글자부터 글 본문을 찾고 결과는 `N개 파일, M줄` 요약 아래 파일별로 묶여 위치와 발췌로 보인다. 결과를 누르면 그 글의 장·절로 가고 패널은 검색 화면에 남는다. 색인은 검색 화면을 처음 열 때만 받는다.

**Blocked by:** 16 (마지막 패널 화면 기억), 17 (검색 색인 빌드)

**Status:** ready-for-agent

참고: 스펙 [블로그 디테일 1차](../spec.md) "검색 화면", 결정 [패널 검색 화면과 명령 팔레트의 모양](05-search-panel-and-palette.md). 모양은 브랜치 `prototype/search-panel-and-palette`(`fd9ec0e`, `?variant=A`)에서 가져오되 코드는 옮기지 않는다.

- [ ] 패널 화면이 프로필 → 탐색기 → 검색 순서로 셋이 된다(활동 막대, 좁은 화면 전환 버튼). 파일을 열 때 지금 화면이 검색이면 검색 화면을 그대로 둔다. 마지막 패널 화면 기억(티켓 16)이 검색 화면도 저장한다
- [ ] 색인 주소는 창 틀 props로 받는다(디자인 시스템은 블로그 내용을 모른다, ADR 0002). 검색 화면 코드는 처음 쓸 때 불러오는 청크라 첫 화면 JS에 없다
- [ ] 색인을 받지 못하면 "검색 색인을 불러오지 못했습니다"와 `다시 시도` 버튼을 보인다
- [ ] 찾기 순수 모듈: NFD + 소문자 부분 일치, 두 글자 미만 무시, 원래 문자열 위치의 일치 범위, 음절 중간 일치는 음절 전체로 넓힘, 순위(제목 일치 → 일치 줄 수 → 최신), 파일당 다섯 줄 상한과 남은 줄 수, 위치 문구(`04 장 › 절 · Ln N`, 장 전 블록은 `Ln N`)
- [ ] 단위 테스트가 위 규칙을 모두 덮는다. "개바"→"개발", "발자"→"개발자" 사례를 넣는다
- [ ] 결과 줄 위는 위치(모노), 아래는 발췌(세리프, 최대 두 줄, 첫 일치가 보이게 앞을 `…`로 자름)다. 일치한 글자는 marker로 칠한다. 파일 줄은 접힘 삼각형·파일 이름·일치 수이고 누르면 접고 편다. 다섯 줄을 넘으면 `… N줄 더`로 편다. 결과가 없으면 `결과 없음`이다
- [ ] 결과 링크는 절 → 장 → 글 맨 위 순으로 앵커를 고르는 진짜 `<a href>`다. 좁은 화면에서는 누르면 서랍이 닫히고 다시 열면 검색어와 결과가 그대로다. 검색어는 메모리에만 있어 새로고침하면 비워진다
- [ ] 빌드 결과물 테스트: 첫 화면 HTML이 검색 화면 청크를 미리 불러오지 않는다
- [ ] `pnpm qa`: 검색 → 결과 누르기 → 패널이 검색 화면에 남음 → 새로고침 뒤에도 검색 화면. 검색 화면을 열기 전에는 `/search-index.json` 요청이 없다. 결과가 있는 검색 화면을 세 폭 × 두 테마로 axe에 넣는다
- [ ] `Shell` Storybook에 검색 화면 스토리가 있다
- [ ] `pnpm verify`·`pnpm qa` 통과

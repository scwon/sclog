# 18: 패널 검색 화면

**What to build:** 활동 막대의 돋보기(좁은 화면은 서랍의 `검색` 버튼)로 패널을 검색 화면으로 바꾼다. 두 글자부터 글 본문을 찾고 결과는 `N개 파일, M줄` 요약 아래 파일별로 묶여 위치와 발췌로 보인다. 결과를 누르면 그 글의 장·절로 가고 패널은 검색 화면에 남는다. 색인은 검색 화면을 처음 열 때만 받는다.

**Blocked by:** 16 (마지막 패널 화면 기억), 17 (검색 색인 빌드)

**Status:** done

참고: 스펙 [블로그 디테일 1차](../spec.md) "검색 화면", 결정 [패널 검색 화면과 명령 팔레트의 모양](05-search-panel-and-palette.md). 모양은 브랜치 `prototype/search-panel-and-palette`(`fd9ec0e`, `?variant=A`)에서 가져오되 코드는 옮기지 않는다.

- [x] 패널 화면이 프로필 → 탐색기 → 검색 순서로 셋이 된다(활동 막대, 좁은 화면 전환 버튼). 파일을 열 때 지금 화면이 검색이면 검색 화면을 그대로 둔다. 마지막 패널 화면 기억(티켓 16)이 검색 화면도 저장한다
- [x] 색인 주소는 창 틀 props로 받는다(디자인 시스템은 블로그 내용을 모른다, ADR 0002). 검색 화면 코드는 처음 쓸 때 불러오는 청크라 첫 화면 JS에 없다
- [x] 색인을 받지 못하면 "검색 색인을 불러오지 못했습니다"와 `다시 시도` 버튼을 보인다
- [x] 찾기 순수 모듈: NFD + 소문자 부분 일치, 두 글자 미만 무시, 원래 문자열 위치의 일치 범위, 음절 중간 일치는 음절 전체로 넓힘, 순위(제목 일치 → 일치 줄 수 → 최신), 파일당 다섯 줄 상한과 남은 줄 수, 위치 문구(`04 장 › 절 · Ln N`, 장 전 블록은 `Ln N`)
- [x] 단위 테스트가 위 규칙을 모두 덮는다. "개바"→"개발", "발자"→"개발자" 사례를 넣는다
- [x] 결과 줄 위는 위치(모노), 아래는 발췌(세리프, 최대 두 줄, 첫 일치가 보이게 앞을 `…`로 자름)다. 일치한 글자는 marker로 칠한다. 파일 줄은 접힘 삼각형·파일 이름·일치 수이고 누르면 접고 편다. 다섯 줄을 넘으면 `… N줄 더`로 편다. 결과가 없으면 `결과 없음`이다
- [x] 결과 링크는 절 → 장 → 글 맨 위 순으로 앵커를 고르는 진짜 `<a href>`다. 좁은 화면에서는 누르면 서랍이 닫히고 다시 열면 검색어와 결과가 그대로다. 검색어는 메모리에만 있어 새로고침하면 비워진다
- [x] 빌드 결과물 테스트: 첫 화면 HTML이 검색 화면 청크를 미리 불러오지 않는다
- [x] `pnpm qa`: 검색 → 결과 누르기 → 패널이 검색 화면에 남음 → 새로고침 뒤에도 검색 화면. 검색 화면을 열기 전에는 `/search-index.json` 요청이 없다. 결과가 있는 검색 화면을 세 폭 × 두 테마로 axe에 넣는다
- [x] `Shell` Storybook에 검색 화면 스토리가 있다
- [ ] `pnpm verify`·`pnpm qa` 통과

## Comments

### 2026-10-27 구현 (브랜치 `blog-details/18-search-view`)

**결정**

- 정규화는 따로 떼어 낸 순수 모듈 `components/Shell/match.logic.ts`에 두었다. `normalizeForMatch(text)`(NFD + 소문자)와 `matchRanges(text, query)`(원래 문자열의 UTF-16 범위 `MatchRange[]`)를 내보내고, 명령 팔레트의 파일 모드도 이것을 쓴다. 앞뒤 공백 다듬기와 두 글자 하한은 부르는 쪽이 정한다. 검색 화면은 `search.logic.ts`의 `searchTerm`이 맡는다. 팔레트는 빈 입력에서도 모든 글을 보여야 하기 때문이다.
- 일치 범위는 정규화한 글자마다 원래 글자의 시작·끝 오프셋을 적은 대응표로 되돌린다. 그래서 음절 중간에서 시작하거나 끝나는 일치는 따로 처리하지 않아도 음절 전체로 넓어진다. 겹치거나 맞닿은 범위는 하나로 합친다(`개발개발`에서 `개발` → 범위 하나).
- 찾기는 `search.logic.ts`의 `searchPosts(index, query)`가 맡는다. 두 글자 미만이면 `null`을 돌려주고, 그 밖에는 `{ files, lines }`를 돌려준다. 제목 일치는 글 `title`을 같은 정규화로 부분 일치시켜 판정한다. 같은 순위끼리는 색인 순서(최신 먼저)를 따른다. 빈 `text` 블록은 일치할 수 없으니 따로 거르지 않는다. `capHits(hits, expanded)`는 다섯 줄 상한과 남은 줄 수를, `excerpt(text, ranges)`는 발췌를 돌려준다.
- 발췌는 첫 일치 앞 12자에서 자르되, 그 12자 안에 공백이 있으면 첫 공백 뒤에서 잘라 낱말 가운데를 피한다(`…gs: [` 대신 `…["회고", …`). DOM에는 200자까지만 넣고, 나머지 말줄임은 `line-clamp-2`에 맡긴다.
- 상태는 두 갈래로 나눴다. 검색어와 포커스 요청은 창 틀 번들에 실리는 작은 스토어 `stores/search.ts`(`$searchQuery`, `setSearchQuery`, `$searchFocus`, `requestSearchFocus`)에 둔다. 색인을 받는 상태는 검색 화면 청크(`SearchView.tsx`) 안의 atom에 주소별로 둔다. 같은 주소는 한 번만 받고, 실패하면 `다시 시도`로 다시 받는다.
- ⌘⇧F 진입점(티켓 22): 창 틀 안에서 `updatePanel((_, wide) => showView('search', wide))`를 부른 뒤 `requestSearchFocus()`를 부르면 된다. 청크를 아직 불러오지 않았어도 검색 화면이 그려질 때 요청을 보고 포커스를 준 뒤 요청을 내린다. 활동 막대 돋보기도 같은 요청을 보낸다. 스펙은 ⌘⇧F의 포커스만 정했지만 VS Code와 같게 했다.
- 검색 화면은 `React.lazy(() => import('./SearchView'))`와 `Suspense`로 그린다. 서버 HTML은 늘 프로필이나 탐색기로 그리므로(`startView(null, kind)`) 서버에서는 검색 화면을 그리지 않는다. 색인 주소는 `ShellProps.searchIndexUrl`(필수)로 받고, `BaseLayout`이 `/search-index.json`을 넘긴다.
- 파일 묶음의 접힘과 `… N줄 더` 펼침은 검색어가 바뀌면 처음으로 돌아간다(묶음 key에 검색어를 넣음). 색인을 받는 동안 요약 줄에는 "색인을 불러오는 중"이 뜨고, 두 글자 미만이면 요약 줄이 빈다. 요약 줄은 `<output>`(status)이라 스크린 리더가 결과 수를 읽는다.
- 빌드 결과물 테스트는 `dist/_astro/SearchView.*.js` 청크가 따로 있는지 본다. 그리고 어떤 HTML에도 그 이름이 없는지(`modulepreload` 포함), 어떤 청크도 그것을 정적으로 import하지 않는지 본다. 정적 import로 바꿔 빌드하면 실패하는 것도 확인했다.
- Storybook `Shell`에 `Search`(색인 고정값을 data URL로 넘김, `개바`)와 `SearchIndexError`를 더했다. 마지막 패널 화면이 sessionStorage에 남으므로 meta의 `beforeEach`가 스토리마다 탐색기와 빈 검색어로 되돌린다.
- qa: `nav.mjs` 끝에 검색 단계(열기 전 색인 요청 없음 → 돋보기 → 입력창 포커스 → `개발` → 첫 결과 → 창 틀 유지·검색 화면·검색어 유지 → 새로고침 뒤 검색 화면·빈 검색어)를 넣었다. `a11y.mjs`는 폭×테마마다 결과가 있는 검색 화면을 본다. 지침대로 `pnpm qa`는 돌리지 않았다. `run.mjs`의 포트만 잠시 4318로 바꿔 돌렸고, a11y는 64회에 위반 0, nav는 모두 통과했다. 첫 실행에서는 검색과 상관없는 앞 단계 "테마가 바뀜"이 한 번 `light → light`로 실패했고, 다시 돌리니 통과했다. 좁은 화면(390px)에서 결과를 누르면 서랍이 닫히고 다시 열면 검색어와 결과가 그대로인 것은 ego로 따로 확인했다. 마지막 체크박스의 `pnpm qa`는 통합 브랜치에서 확인할 몫으로 남긴다.

- 통합 브랜치(티켓 19·20까지)를 합치면서 팔레트 파일 모드(`palette.logic.ts`)가 따로 갖던 같은 정규화 함수를 지우고 `match.logic.ts`의 `normalizeForMatch`를 가져다 쓰게 했다. 합친 뒤 4318 포트에서 nav는 모두 통과했다. a11y는 1440 light 글 화면에서 `color-contrast (.pl-1 > span[aria-hidden="true"])`(티켓 20의 탐색기 읽음 꼬리표) 하나가 걸렸고, 검색 단계를 뺀 a11y도 실패했다. 이 티켓의 변경과는 무관해 보여 손대지 않았다.

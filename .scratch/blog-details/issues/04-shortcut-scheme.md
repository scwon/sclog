# 04: 단축키 체계

**Type:** grilling

**Blocked by:** 없음

**Status:** resolved

지도: [블로그 디테일 1차](../map.md)

## Question

이 블로그의 키보드 단축키는 어떤 체계를 따르는가?

- VS Code 조합 키(⌘P 파일 열기, ⌘B 패널 열고 닫기, ⌘W 탭 닫기)를 따를지, 한 글자 키(j/k 글 이동, `[` `]` 장 이동)를 쓸지, 둘 다일지
- 브라우저 기본 단축키(⌘W·⌘P 인쇄 등)와 겹칠 때 무엇을 양보하는가
- 스크린 리더·입력창 입력과 부딪히지 않게 하는 규칙(어디서 단축키를 끄는가)
- `?`로 여는 단축키 도움말에 무엇을 보여 주는가
- 좁은 화면·터치 기기에서는 어떻게 하는가

## Answer

VS Code의 조합 키만 쓰고 한 글자 키는 두지 않는다. j/k, `[` `]`, `?` 모두 없다. 한 글자 키는 IDE보다 GitHub·Gmail의 관습에 가깝고, WCAG 2.1.4 때문에 끄는 설정까지 따로 둬야 한다.

**지금 붙이는 키**

| 키 | 동작 |
| --- | --- |
| ⌘P | 파일 열기 팔레트 |
| ⌘B | 패널 열고 닫기(마지막 패널 화면으로 열림) |
| ⌘⇧F | 패널 검색 화면을 열고 입력창에 포커스 |

윈도·리눅스에서는 ⌘ 대신 Ctrl로 받고 표기도 `Ctrl+P`처럼 바꾼다. OS 판별은 첫 화면 HTML에 넣지 않고 툴팁을 처음 그릴 때 한다.

**브라우저와 겹칠 때**

1. 브라우저가 페이지에 넘기지 않는 키(⌘W·⌘T·⌘N·⌘Q·⌃Tab)는 쓰지 않는다. 그래서 탭 닫기 키는 없다. 탭 사이 이동은 지금 있는 ←/→로 한다.
2. 가로챌 수 있어도 독자가 자주 쓰는 브라우저 키(⌘F·⌘L·⌘R·⌘D·⌘+/−)는 건드리지 않는다. 개발자 도구 키도 여기에 든다. ⌘⇧E(탐색기)를 뺀 것은 Firefox 윈도의 Ctrl+Shift+E가 네트워크 도구라서다. ⌘⇧P는 Firefox 사생활 보호 창 키라서 쓰지 않는다.
3. 가로채는 키는 ⌘P(인쇄 대신)와 ⌘B(Firefox 북마크 사이드바 대신)뿐이다.

새 디테일에 키를 붙이려면 VS Code에 대응하는 키가 있고 위 규칙을 통과해야 한다. 경로 표시줄 장 드롭다운의 ⌘⇧O도 1차 묶음에 들어가면 이 기준으로 본다. 키마다 Chrome·Safari·Firefox(맥·윈도)와 겹치는지는 스펙 단계에서 표로 확인하고, 겹치면 뺀다.

**단축키를 끄는 때**

- 입력창·textarea·contenteditable에 포커스가 있을 때. 다만 팔레트 입력창의 Esc·↑↓·Enter는 받는다
- 한글을 조합하는 중(`isComposing`)
- 팔레트나 대화상자가 열려 있을 때. 이때는 그 창의 키만 받는다

조합 키는 스크린 리더 읽기 모드와 거의 겹치지 않아서 끄기 설정은 두지 않는다.

**Esc**는 맨 위 층 하나만 닫는다(팔레트, 그다음 좁은 화면의 겹침 패널). 넓은 화면에 붙은 패널은 ⌘B로 닫는다. 지금 `Shell.tsx`의 겹침 패널 Esc가 이미 이렇게 동작한다.

**도움말**은 따로 창을 두지 않는다. ⌘P 팔레트에서 `>`를 치면 명령 목록이 나오고 줄마다 단축키가 붙는데, 이것이 도움말이다. 입력창 안내 문구("> 를 입력하면 명령")와 버튼 툴팁의 키 표기로 찾아 들어오게 한다.

**좁은 화면·터치**: 키 처리는 화면 폭과 상관없이 늘 켜 둔다(키보드를 단 iPad). 툴팁의 키 표기와 안내 문구는 `(hover: hover) and (pointer: fine)`일 때만 보인다. 터치 몸짓으로 대신하지는 않는다.

# 12: 다음 파일 줄

**What to build:** 글 끝 댓글 앞의 이동 줄이 흐름 로그의 링크 줄 모양으로 바뀐다. 맨 위에 다음 파일 줄(`newer-post.mdx →` + 글 제목)이 오고 그 아래에 `posts.log`와 `맨 위로`가 놓인다. 다음 파일은 탐색기에서 같은 폴더 안 바로 다음으로 새 글 하나다. 없으면 그 줄만 그리지 않는다. 줄 전체가 빌드 때 HTML로 나와서 JS 없이도 동작한다.

**Blocked by:** None (can start immediately)

**Status:** done

참고: 스펙 [블로그 디테일 1차](../spec.md) "다음 파일", 결정 [다음 파일 열기](10-next-file.md).

- [x] 다음 파일을 정하는 순수 함수가 있다. 탐색기 트리와 지금 글 URL을 받아 같은 폴더의 바로 다음 새 글을 돌려주고 없으면 `null`을 돌려준다. 폴더를 넘지 않는다. 창 틀(티켓 22의 팔레트 명령)도 쓸 수 있게 디자인 시스템 쪽에 둔다
- [x] 단위 테스트: 같은 폴더의 다음 새 글, 폴더의 가장 새 글은 `null`, 글 한 편뿐일 때 `null`
- [x] 글 끝 줄은 흐름 로그 링크 줄과 같은 모양이고 순서는 다음 파일 → `posts.log` → `맨 위로`다. 제목이 길면 한 줄에서 말줄임한다. 좁은 화면도 같은 모양이다

- [x] 빌드 결과물 테스트: 폴더의 가장 새 글이 아니면 다음 파일 줄이 있고 가장 새 글이면 없다. `posts.log`·`맨 위로` 줄은 늘 있다
- [x] 시험용 글은 테스트 고정값으로만 만들고 `src/content`에 넣지 않는다

## Comments

### 2026-10-27 구현 (브랜치 `blog-details/12-next-file-line`)

**결정**

- 순수 함수는 `nextFile(tree, url)`이고 `src/design-system/components/Shell/tree.logic.ts`에 두어 `@/design-system`으로 내보냈다. 트리에 날짜가 없으므로 "바로 다음으로 새 글"은 같은 폴더 목록에서 바로 앞 항목으로 정했다. 폴더 안 순서는 `buildTree`가 `getPublishedPosts`의 최신순을 그대로 따른다는 데 기댄다. 트리에 없는 URL(홈 등)도 `null`이다.
- 줄 목록은 `src/utils/ide.ts`의 `docEndLinks(next)`가 만들고 `BlogPost.astro`가 그린다. 순서와 라벨(`{파일 이름} →`), 이름("다음 파일: {제목}")을 이 함수의 단위 테스트가 고정값으로 본다.
- 접근 가능한 이름은 링크의 `aria-label`로 줬다. 라벨·점선·메모(글 제목)가 한 링크 안에 있어서 제목을 눌러도 다음 글로 간다. 꼬리표 자리 `<span class="doc-end-mark" data-next-file-mark>`는 링크 밖, 메모 바로 뒤에 둔 빈 칸이다. 그래서 티켓 20이 넣을 "읽음" 글자가 링크 이름을 바꾸지 않고 링크 다음에 읽힌다. 칸이 비어 있지 않을 때만 왼쪽 여백 8px이 생긴다.
- 모양은 흐름 로그 링크 줄(`.flow-dir-label`·`.flow-dir-rule`·`.flow-dir-count`)과 같은 글꼴·색·점선 값을 쓰는 `.doc-end-*`로 새로 정의했다. 글 화면에는 흐름 로그의 줄 번호 칸과 레일이 없어서 격자를 빌려 오지 않았다. 라벨과 점선(최소 24px)은 줄지 않고 메모만 한 줄에서 말줄임한다. 결정 티켓의 그림대로 `posts.log`·`맨 위로` 줄에는 점선과 메모가 없다. 이전 `← posts.log`의 화살표는 뺐다.
- 빌드 결과물 테스트는 글 페이지의 `data-file-*`와 `article:published_time`으로 트리를 다시 짓고, 글마다 `nextFile`의 답과 글 끝 줄(주소·라벨·이름·꼬리표 자리)을 맞대어 본다. 지금 글이 한 편뿐이라 실제 빌드에서는 "줄이 없음" 쪽만 돈다. 같은 연도의 임시 글을 커밋하지 않고 잠깐 넣어 "줄이 있음" 쪽(이름에 `&`가 든 제목 포함)이 통과하는 것을 확인했다.
- ego-browser로 1400px·390px에서 긴 제목이 한 줄로 말줄임되는 것(메모 565px → 493px·147px)과 세 줄 모두 높이 28px인 것을 확인했다.

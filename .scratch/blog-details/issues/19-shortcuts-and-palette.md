# 19: 단축키와 팔레트로 파일 열기

**What to build:** ⌘P(윈도·리눅스는 Ctrl+P)를 누르면 제목 표시줄 아래 가운데에 명령 팔레트가 뜬다. 파일 이름이나 제목 일부를 쳐서 ↑↓·Enter로 글을 연다. Esc·바깥 클릭·고르기로 닫히고 닫히면 포커스가 연 자리로 돌아온다. ⌘B는 패널을 마지막 화면으로 여닫는다. Esc는 맨 위 층 하나만 닫는다. 입력창에서 글을 치거나 한글을 조합하는 중에는 단축키가 동작하지 않는다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

참고: 스펙 [블로그 디테일 1차](../spec.md) "단축키"·"명령 팔레트", 결정 [단축키 체계](04-shortcut-scheme.md)·[패널 검색 화면과 명령 팔레트의 모양](05-search-panel-and-palette.md). 모양은 브랜치 `prototype/search-panel-and-palette`(`?variant=A`).

- [ ] 첫 단계: ⌘⇧F가 Chrome·Safari·Firefox × 맥·윈도에서 페이지에 넘어오는지 직접 눌러 확인하고 결과를 스펙 Comments에 표로 남긴다. 받을 수 없는 조합이 있으면 티켓 22에서 ⌘⇧F를 빼도록 그 티켓에 적는다
- [ ] 키 판정 순수 함수가 있다. 키 이벤트 모양(`key`, 수정 키, `isComposing`, 포커스 대상 종류)과 맥락(팔레트 열림, 겹침 패널 열림, 플랫폼)을 받아 동작 하나나 `null`을 돌려준다. 창 틀은 `document`에 리스너 하나만 건다
- [ ] 맥은 `metaKey`만, 그 밖은 Ctrl만 받는다. OS 판별은 키 표기를 처음 그릴 때 하고 첫 화면 HTML에는 넣지 않는다
- [ ] 끄는 때: 입력창·textarea·contenteditable 포커스(팔레트 입력창의 Esc·↑↓·Enter는 예외), `isComposing`, 팔레트가 열려 있을 때(팔레트 키만). 열린 팔레트에서 ⌘P는 기본 동작만 막는다
- [ ] 가로채는 브라우저 키는 ⌘P와 ⌘B뿐이고 나머지 브라우저 키는 `null`이다
- [ ] 단위 테스트가 위 규칙과 Esc 층 순서(팔레트 → 좁은 화면 겹침 패널)를 덮는다
- [ ] 팔레트는 `role="dialog"`·`aria-modal`이고 안은 콤보박스 + 목록 패턴(`aria-activedescendant`)이다. 폭은 600px 안팎이고 좁은 화면에서는 양옆 16px 여백만 둔다. 처음 쓸 때 불러오는 청크다
- [ ] 파일 모드 순수 모듈: 탐색기 트리 props를 검색 화면과 같은 정규화로 거른다. 순위는 이름이 검색어로 시작 → 이름에 포함 → 제목에 포함 → 트리 순서다. 빈 입력은 모든 글을 트리 순서로 보인다. 단위 테스트가 덮는다
- [ ] 줄마다 파일 이름, 흐린 글자로 폴더와 제목이 보이고 맨 아래에 "본문에서 찾으려면 ⌘⇧F" 안내가 있다
- [ ] 단축키 기준(VS Code 대응 키, 브라우저 키 양보, 겹침 확인표)을 `docs/agents/`에 한 쪽으로 남긴다
- [ ] `pnpm qa`: ⌘P → 입력 → Enter로 글 열기 → 다시 열고 Esc로 닫으며 포커스 복귀, ⌘B로 패널 여닫기. 열린 팔레트를 세 폭 × 두 테마로 axe에 넣는다
- [ ] 빌드 결과물 테스트: 첫 화면 HTML이 팔레트 청크를 미리 불러오지 않는다
- [ ] `pnpm verify`·`pnpm qa` 통과

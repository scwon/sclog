# 05: 패널 검색 화면과 명령 팔레트의 모양

**Type:** prototype

**Blocked by:** 01, 04

**Status:** resolved

지도: [블로그 디테일 1차](../map.md)

## Question

검색을 활동 막대의 아이콘으로 여는 패널 화면(탐색기·프로필 옆)과 ⌘P 명령 팔레트로 어떻게 보여 줄 것인가?

- 패널 검색 화면: 입력창, 결과 줄의 모양(파일 이름·일치한 줄·장), 결과를 누르면 무엇이 열리는가
- 명령 팔레트: 패널 검색과 같은 검색인가, 파일 이름만 찾는 별개 도구인가. 어디에 뜨고 어떻게 닫히는가
- 둘이 같은 결과를 보여 준다면 하나로 합칠지
- 좁은 화면에서는 어떻게 여는가(활동 막대가 숨으므로)
- 팔레트의 `>` 명령 목록: 단축키 도움말을 겸한다([단축키 체계](04-shortcut-scheme.md)). 명령 줄과 키 표기가 어떻게 생겼는지, 입력창 안내 문구를 어떻게 둘지
- ⌘⇧F는 패널 검색 화면을 열고 입력창에 포커스를 준다. 팔레트 안에서 받는 키는 Esc·↑↓·Enter다
- 패널이 세 화면(탐색기·검색·프로필)이 되면 GLOSSARY의 **패널** 정의를 고친다

`/prototype`의 UI 갈래로 변형 두세 개를 만들어 비교한다.

## Answer

변형 A(VS Code 그대로)로 정했다. 패널 검색 화면과 명령 팔레트는 서로 다른 도구로 둔다. 비교한 세 변형은 브랜치 `prototype/search-panel-and-palette`(커밋 `fd9ec0e`)의 `src/design-system/components/Shell/SearchPrototype.prototype.tsx`에 있고, 개발 서버에서 `?variant=A|B|C`로 바꿔 볼 수 있다.

**패널 검색 화면** (활동 막대의 돋보기, ⌘⇧F)
- 맨 위에 입력창이 있고 그 아래에 `N개 파일, M줄` 요약이 붙는다. 두 글자부터 찾는다.
- 결과는 파일별로 묶는다. 파일 줄에는 접힘 삼각형·파일 이름·일치 수를 두고, 그 아래 일치한 줄을 늘어놓는다.
- 일치한 줄 하나는 두 줄로 보인다. 위 줄은 위치(`04 개발자란? › 3~4년차 · Ln 21`, 모노)이고, 아래는 본문 발췌(세리프, 최대 두 줄)다. 일치한 글자는 형광 띠(`marker`)로 칠한다. 입력 중인 음절("개바")은 음절 전체를 칠한다.
- 결과를 누르면 그 글의 해당 장·절 앵커로 간다. 패널은 탐색기로 바뀌지 않고 검색 화면에 남는다. 지금의 `viewForFile` 규칙에서 검색 화면만 예외가 된다.

**명령 팔레트** (⌘P)
- 제목 표시줄 바로 아래 가운데에 뜬다(폭 600px 안팎). 입력창 아래 목록이 있고 ↑↓·Enter로 고른다. Esc, 바깥 클릭, 고르기로 닫히고 닫히면 연 자리로 포커스를 돌려준다.
- 파일 이름(과 제목)으로만 찾는다. 본문은 찾지 않으며, 맨 아래에 "본문에서 찾으려면 ⌘⇧F" 안내를 단다.
- 입력창이 `>`로 시작하면 명령 목록이 나온다. 줄마다 단축키가 붙고, 이것이 단축키 도움말이다([단축키 체계](04-shortcut-scheme.md)).

**합치지 않는 이유**: 하나로 합친 B는 파일과 본문이 한 목록에 섞여 길어지고, 좁은 화면에서는 일치한 글자가 줄 밖으로 밀려 강조가 보이지 않았다. 결과를 에디터 자리에 쌓은 C는 읽던 글을 덮었다.

**좁은 화면**: 서랍의 화면 전환 버튼에 `검색`이 더해진다(프로필·탐색기·검색). 팔레트를 여는 버튼은 따로 두지 않는다. 터치에는 단축키를 대신하는 동작이 없다는 결정을 따르고, 명령마다 이미 버튼이 있기 때문이다.

**용어**: `GLOSSARY.md`의 패널 정의를 세 화면으로 고치고 **검색 화면**과 **명령 팔레트**를 더했다.

**프로토타입에서 확인하지 못한 것**: 실제 글이 1편이라 `(가짜)` 글 넷을 섞어 모양을 봤다. 결과가 많을 때의 상한(파일당 줄 수 등)과 순위(제목 일치 우선 등)는 스펙 단계에서 정한다. 프로토타입의 `Ln`은 문단 순번이고, 실제로는 글 화면의 줄 번호와 맞춰야 한다.

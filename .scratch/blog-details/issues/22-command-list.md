# 22: 명령 목록과 ⌘⇧F

**What to build:** 팔레트에 `>`를 치면 명령 목록과 단축키가 나온다. 이 목록이 이 블로그의 단축키 도움말이다. 명령으로 검색·패널 화면·테마·다음 파일·읽기 기록 지우기를 실행한다. ⌘⇧F(Ctrl+Shift+F)는 패널 검색 화면을 열고 입력창에 포커스를 준다. 마우스를 쓰는 독자는 활동 막대 툴팁에서 키를 본다.

**Blocked by:** 12 (다음 파일 줄), 18 (패널 검색 화면), 19 (단축키와 팔레트로 파일 열기), 20 (읽기 기록과 읽은 글 꼬리표)

**Status:** done

## Comments

### 2026-10-27 구현 (브랜치 `blog-details/22-command-list`)

**사람 확인 대기**

- ⌘⇧F의 겹침 확인(티켓 19 첫 단계)은 아직 하지 않았다. 받을 수 있다고 보고 붙였다. 붙은 키는 `shortcuts.logic.ts`의 `SHORTCUT_KEYS` 한곳에서 정한다. 판정·명령 목록·팔레트 맨 아래 안내·활동 막대 툴팁이 모두 이 값을 읽으므로, 빼야 하면 `search`를 `null`로 바꾸면 된다. 그때 지울 것은 `nav.mjs`의 ⌘⇧F 단계뿐이다. 이 경로는 단위 테스트가 덮는다(키가 `null`이면 판정이 `null`이고 명령 줄의 키 칸이 빈다).
- 마지막 항목은 `pnpm verify`만 통과했다. 같은 QA 스크립트를 이 브랜치 빌드에 4322 포트로 돌렸다. `nav.mjs`는 전부 통과했다(⌘⇧F로 검색 화면이 열리고 입력창에 포커스가 가는 단계 포함). `a11y.mjs`는 axe를 79회 돌렸고, 팔레트와 `>` 명령 목록은 세 폭 × 두 테마 모두 위반이 없었다. 위반은 `1440 light 이어 읽기`의 `color-contrast`(`.pl-1 > span[aria-hidden]`, 탐색기 읽음 꼬리표) 하나였다. 이 티켓이 건드리지 않은 티켓 20·21 영역이다.

**결정**

- 명령 모드는 `palette.logic.ts`의 `isCommandQuery`·`paletteCommands(query, { hasNextFile, platform })`가 맡는다. 줄은 `{ id, label, keys }`이고, `keys`는 플랫폼에 맞춘 표기이거나 `null`이다. 명령 id는 `open-file`·`find-in-posts`·`toggle-panel`·`show-explorer`·`show-profile`·`toggle-theme`·`open-next-file`·`clear-history`다.
- 거르기는 파일 모드와 같은 `normalizeForMatch`로 부분 일치만 보고 목록 순서를 지킨다. 파일 모드의 "이름이 검색어로 시작"하는 순위는 넣지 않았다. 지금 명령 이름으로는 순서가 바뀌는 경우가 없어서다.
- `파일 열기`를 고르면 팔레트가 닫히지 않고 입력을 비워 파일 모드로 돌아간다. 다른 명령은 창 틀(`Shell`의 `runCommand`)이 팔레트를 닫아 포커스를 연 자리로 돌려준 뒤 실행한다. `Palette`에 더한 props는 `hasNextFile`과 `onCommand(id)`다.
- `읽기 기록 지우기`는 프로필 칸과 같은 `clearReadingHistory()`를 부른다. 팔레트가 닫히면 보이는 변화가 없을 수 있어서, 스펙에 없던 상태줄 알림 "읽기 기록을 지웠습니다"를 더했다.
- ⌘⇧F와 `본문에서 찾기`는 `openSearch`를 같이 쓴다. 검색 화면을 연 다음 프레임에 `requestSearchFocus()`를 보낸다. 바로 보내면 좁은 화면(1100px 미만)에서 겹침 패널이 열릴 때 패널로 옮기는 포커스가 입력창 포커스를 덮어쓴다(검색 화면 청크를 이미 불러온 두 번째부터). ego로 900px·390px에서 두 번씩 눌러 매번 입력창에 포커스가 가는 것을 확인했다. 활동 막대의 검색 버튼(`pick`, 티켓 18)은 아직 바로 보내므로, 760~1099px에서 같은 덮어쓰기가 날 수 있다. 이번에는 고치지 않았다.
- 키 표기와 `>` 안내는 `(hover: hover) and (pointer: fine)`일 때만 보인다. 키 표기 `<kbd>`와 맨 아래 안내 줄은 Tailwind 임의 변형 `[@media(hover:hover)_and_(pointer:fine)]:`으로 숨긴다. 안내 줄은 문장 전체가 키 안내라 줄째 숨겼다. placeholder는 CSS로 바꿀 수 없어서 `matchMedia`로 고르고, 터치 화면에서는 "파일 이름으로 찾기"만 보인다. 입력창의 `aria-label`은 늘 전체 안내 문구다. 명령 모드에서는 맨 아래 안내를 숨기고, 결과가 없으면 "맞는 명령이 없습니다"를 보인다. 목록 이름은 모드에 따라 `파일`·`명령`이다.
- 툴팁은 radix `Tooltip` 대신 활동 막대 버튼의 `title`로 붙였다. 첫 화면 JS에 popper를 더하지 않으려는 것이고, Tabs와 탐색기 줄도 이미 `title`을 쓴다. 플랫폼은 `useSyncExternalStore`로 읽는다(서버 스냅샷 `null`). 그래서 서버 HTML과 첫 하이드레이션은 `검색`이고, 그 뒤 `검색 (⌘⇧F)`·`탐색기 (⌘B)`가 된다. 이전의 `platform` 상태(팔레트를 열 때 정함)는 이 훅으로 바꿨다.
- Storybook에 `Commands`·`CommandsWithoutNextFile` 이야기를 더했다(play 함수로 `>`를 친다).

**측정값**

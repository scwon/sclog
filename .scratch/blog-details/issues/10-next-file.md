# 10: 다음 파일 열기

**Type:** grilling

**Blocked by:** 없음

**Status:** resolved

지도: [블로그 디테일 1차](../map.md)

## Question

글 끝에서 권하는 "다음 파일"은 무엇이고, 어디에 어떤 모양으로 두는가? 글이 여러 편 쌓인다는 전제로 정한다([1차 묶음](06-first-bundle.md)).

- 무엇이 다음인가: 시간순으로 다음(또는 이전) 글인지, 같은 태그의 글인지, 둘 다인지. 다음 글이 없을 때는 무엇을 보이는가
- 읽은 글은 건너뛰는가([이어 읽기와 읽은 글의 겉모습](08-resume-and-read-marks.md)과 맞춘다)
- 글 끝 어디에 두는가: 흐름 로그의 링크 줄 모양인지, 꼬리(댓글) 앞인지 뒤인지
- 단축키를 붙이는가. [단축키 체계](04-shortcut-scheme.md)의 기준(VS Code에 대응하는 키가 있고 브라우저 키와 겹치지 않을 것)을 따른다
- JS 없이도 보이는 정적 링크로 만드는가

## Answer

다음 파일은 탐색기에서 같은 폴더 안, 바로 다음으로 새 글 하나다. 지금 폴더는 연도 폴더이고, 시리즈 폴더가 생기면 같은 규칙으로 1편 → 2편을 잇는다. 그래서 방향도 하나만 둔다. 이전(더 오래된) 글로 가는 줄은 없다.

- **폴더 경계**: 다음 폴더로 넘어가지 않는다. 시리즈 마지막 편이 다른 시리즈로 이어지면 안 되기 때문이다. 연도 폴더에서 이 규칙 때문에 링크가 빠지는 건 그해 마지막 글 하나뿐이다.
- **다음 글이 없을 때**: 그 줄을 그리지 않는다. "마지막 글입니다" 같은 빈 줄은 두지 않고, 갈 곳은 `posts.log` 줄이 맡는다. 글이 한 편뿐이어도 마찬가지다.
- **읽은 글**: 건너뛰지 않는다. 링크 대상은 빌드 때 정해서 JS가 꺼져도 같다.
- **자리와 모양**: 댓글 앞에 있는 지금의 `doc-end` 이동 줄을 흐름 로그의 링크 줄 몇 개로 바꾼다. 맨 위가 다음 파일이고 그 아래가 `posts.log`, `맨 위로`다. 다음 파일 줄의 라벨은 `newer-post.mdx →`처럼 파일 이름에 화살표를 붙이고, 메모에는 글 제목을 적는다. 제목이 길면 한 줄에서 말줄임한다. 스크린 리더에는 "다음 파일: 제목"으로 읽힌다. 좁은 화면에서도 같은 모양을 쓴다.

```
  newer-post.mdx →   ---- 다음 글 제목
  posts.log
  맨 위로
```

- **읽은 글 표시**: 이 줄에도 [이어 읽기와 읽은 글의 겉모습](08-resume-and-read-marks.md)의 `✓`·`42%`를 메모 뒤에 붙인다. 흐름 로그처럼 HTML이 그려진 뒤 JS가 덧붙인다.
- **단축키**: 두지 않는다. VS Code의 다음 에디터 키(⌃Tab, ⌘⌥→)가 브라우저 탭 전환과 겹친다([단축키 체계](04-shortcut-scheme.md)). 대신 팔레트의 `>` 목록에 `다음 파일 열기` 명령을 하나 더하고, 키 표시는 비운다. 다음 파일이 없는 글에서는 이 명령을 보이지 않는다.
- **정적 링크**: 줄 전체를 빌드 때 HTML로 만든다.

범위 밖으로 둔 것은 같은 태그 기준의 다음 글(관련 글 추천에 가깝고 내용 기능 쪽이다)과 시리즈 폴더 만들기(탐색기 구조와 글 주소를 바꾸는 일이다)다. 이유는 지도의 Out of scope에 적었다.
